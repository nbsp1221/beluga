# 다음 단계와 미해결 항목

현재 구현은 [아키텍처](architecture.md)에 둔다. 아래 순서는 후속 작업 제안이며 엔진·전송 방식·설정 수명에 대한 승인이나 구현 완료를 뜻하지 않는다. 해결 시 항목을 제거하고 지속되는 계약만 소유 문서에 반영한다.

## 연결 이후 결정

- 첨부 범위: 파일을 전송하는 방식과 세션 전환·목록 왕복·새로고침 시 첨부 상태의 수명을 결정한다.
- 실패와 취소: 생성 실패·재시도, 탭 전환과 새로고침을 포함한 제출 상태·취소 UI를 구체화한다. 현 연결은 텍스트 전송과 이력 관찰을 제공한다.
- Linux 운영 인증·TLS 프록시·모델 자격증명 갱신·장시간 실행은 실제 배치에서 검증한다.

완료 조건은 위 선택과 실패 시 동작을 합의하고 필요한 DTO/명령 계약을 정의하는 것이다. 초안·선택은 UI, 실행의 권위 상태와 취소·승인은 Host에 두는 방향으로 검토한다.

## 다음 실제 기능 연결

워크스페이스 범위 셸이 필요해지면 Windows·Linux에서 사용할 실행기를 고르고, 실제 제한 범위와 승인 흐름을 검증한다. 현재 셸 정책은 [아키텍처](architecture.md#에이전트-프리셋과-실행)에 둔다.

실제 파일 패널을 연결한다. 저장/재연결 전후의 메시지·선택·초안 복구 범위를 검증한다. Trajectory의 시간대별 개요는 개별 호출 시작·종료 시각을 저장할 필요가 확인되면 설계한다. 긴 이력의 전송량이나 렌더링이 병목이면 Flue의 페이지 조회와 행 가상화를 검토한다.

### 에이전트 프리셋 선택과 작성

기능과 프리셋이 늘어날 때 선택 화면의 탐색, 버전 이력 표시, 삭제 정책, 파일 가져오기·내보내기의 우선순위를 실제 사용을 기준으로 정한다.

## 출시 전 UI 검증 공백

아래는 이전 검수에서 해결됐다고 주장할 수 없는 항목이다. 브라우저의 모바일 너비·키보드 검사만으로 실기기 검증을 대체하지 않는다.

- iOS Safari/Android의 실제 터치·소프트 키보드·IME 조합, safe-area/notch, 가로·짧은 화면과 pinch zoom. VisualViewport scale 1 처리와 dvh fallback이 Send·설정·파일 닫기를 가리지 않는지 확인한다.
- 실제 200% 브라우저 확대와 reflow. 이전 단축키 시도는 실제 확대를 만들지 못했다. 320px 너비 검사는 확대 검사와 별개다.
- 기본 글자 크기 변경과 긴 지역화 문자열에서 rem 기반 target/Sheet 폭·탭·설정 필드가 유지되는지 확인한다. 모바일 JS 판정은 768px이고 Tailwind md는 48rem이므로 브라우저 기본 글꼴 변경 시 두 기준의 일치도 검증해야 한다. 매우 낮은 가시 높이에서는 editor의 min-height와 max-height가 충돌할 수 있으므로 Send 노출을 실제로 확인한다. 이 점검은 새로운 크기 정책의 승인이 아니다.
- 스크린리더 음성·이름·상태·오류 알림, Windows 고대비/forced-colors 렌더링, OS reduced-motion. 관련 CSS와 키보드 경로가 존재해도 적합성 인증은 아니다.
- 자동 axe 감사와 자동 시각 회귀/픽셀 비교는 아직 없다. 도입 범위는 정하되 수동 상호작용 검사를 대체하지 않는다. 모든 UI 상태·아이콘·투명 합성의 대비를 전수 검증했다고 주장하지 않는다.
- 메뉴 옵션의 포인터 전용 전체 순회와 모바일의 실제 coarse pointer. 기존 모바일 너비 검수 환경은 fine pointer였다. 768px 이상 터치 태블릿에는 현재 모바일 44px 정책이 별도로 적용되지 않는다.
- sidebar resize의 WCAG 2.5.7 단일 포인터 비드래그 대체. 키보드 resize만으로 이 항목을 충족했다고 보지 않으며 제거한 폭 preset을 임의로 복원하지 않는다. 별도 UI 판단이 필요하면 근거와 함께 비동기로 확인한다.

완료 조건은 [디자인 시스템의 흐름별 검수 기준](design-system.md#흐름별-검수-기준)을 두 테마에서 실행하고, 사용한 장치·브라우저·보조기술과 미확인 범위를 작업 증거에 남기는 것이다.

## 성능과 구조의 후속

이전 production build에서 기본 500kB chunk 경고가 남았다. 당시 파일 크기를 현재 측정치로 재사용하지 않는다. 실제 빌드와 번들 분석 후 필요할 때 기능별 로딩 분리를 검토하고 경고 임계값을 올려 숨기지 않는다.

플러그인 사이 import 경계는 현재 전부 자동 강제되지 않는다. 기능이 늘 때 서비스 계약/공개 진입점을 정리하고 필요한 경계 검사만 추가한다. Plugins·Automation·More를 구현할 때 하드코딩된 자리를 등록형 목적지로 바꾸는 범위도 함께 판단한다.

현재 native 요소의 유지 범위와 시각적 대체의 승인 경계는 [디자인 시스템](design-system.md#컴포넌트-선택)에서 관리한다. 그 판단을 미구현 기능의 자동 승인으로 해석하지 않는다.
